## 스위프트에서 퍼포먼스란?

퍼포먼스라는 것은 개발언어에서 여러가지 다양한 노력의 결과가 가져다 주는 사용 속도의 향상과 공간의 절약을 의미합니다. 여기서는 WWDC 2016 session-416 Understanding swift performance를 바탕으로 퍼포먼스 개선을 위한 방법을 소개합니다.

### 스위프트에서 퍼포먼스의 의미

  * Allocation

    * 당신이 코드에서 무엇을 하던 일단 메모리에 저장이 되고 나서야 뭐라도 실행이 가능합니다.

    * 할당 비용을 이해하기 위해 스택과 힙을 구분합니다. 값이 최적화로 레지스터에 남거나 사라질 수도 있습니다.

    * 스택(stack)

      *  빠릅니다

      * 지역 값의 저장에 사용할 수 있습니다. 값 타입이라도 클래스의 저장 프로퍼티, 탈출하는 캡처, existential의 큰 값 등에서는 힙 저장과 관련될 수 있습니다.

      * 개발자가 별도로 객체의 소유권을 선언하거나 해지할 필요가 없이 사용 스코프를 벗어나면 소멸합니다. 참고로 swift던 objective-c with arc 던 결국 클래스는 컴파일러가 객체의 소유권의 선언과 해지를 해주고 있습니다.

      * 값 의미론과 참조 의미론 중 데이터 모델에 맞는 선택을 먼저 하고, 할당 비용은 별도로 확인해야겠죠.

    * 힙(heap)

      *  느립니다

      * 클래스 인스턴스와 배열의 내부 버퍼 등 동적 저장 공간에 사용합니다. 타입 이름만으로 실제 할당을 단정할 수는 없습니다.

      * Swift에서는 ARC가 참조 소유권 관리를 위한 코드를 삽입합니다. 개발자는 강한 참조 순환과 수명 같은 구조를 설계해야 합니다.

      * ARC 이후, 코드상에서는 신경쓰지 않아도 되지만, 구조적으로는 신경쓰지 않으면 예상하지 못한 버그를 발생시키게 됩니다.

  * Reference Counting

    * 객체의 소유권에 대한 선언과 해제

    * 선언과 해지의 빈도수가 적을 수록 좋습니다.

    * ARC 이후, 코드상에서는 보이지 않지만, 컴파일러가 객제의 소유와 해지를 해주고 있습니다. 구조적으로는 객체의 소유에 대해서 신경써야합니다.

  * Method Dispatch

    * method overriding과 특히 관련이 많습니다.

    * 실행할 메소드 구현을 어떻게 결정하는지에 관한 내용입니다. 호출 횟수도 비용에 영향을 주지만 dispatch 방식과는 구별해야 합니다.

    * static

      * final 타입으로 상속을 제한한 경우 속도가 빠릅니다.

    * dynamic

      * 상속이 가능하며 속도가 final function에 비하여 느립니다.

### Allocation 방식의 비교

**스택**

  * 각 작업에 대한 스택포인터의 가감이 전부입니다

**힙**

  * 고수준(복잡하다고 읽으면 됩니다) 데이터 구조

  * 데이터를 쓰기 위한 빈 영역 검색

  * 데이터를 해지하기 위한 메모리 블럭 재배치

  * 멀티스레드를 사용한 경우 스레드 세이프티를 위한 오버헤드 발생

  * 초기화·복사 비용은 저장하는 데이터와 코드 경로에 따라 달라짐

### 결론

  * 작은 값이고 참조 의미론이 필요 없다면 struct로 할당 비용을 줄일 여지가 있습니다. 큰 값의 복사, 내부 참조, 최적화에 따라 결과가 달라지므로 struct의 압승이라고 일반화할 수는 없습니다.

### Reference Counting 의 비교

**struct**

  * 참조를 보유하지 않는 단순 값의 복사는 ARC 연산이 필요하지 않을 수 있습니다. 다만 `String`, `Array`처럼 struct이면서 내부에 참조 저장 공간을 가진 타입도 있으므로, 직접 class 필드가 없다는 것만으로 판단할 수 없습니다.

  * struct가 여러 참조를 보유하면 복사 과정에서 각 참조의 소유권 연산이 필요할 수 있습니다. 실제 비용은 복사 빈도와 컴파일러의 연산 제거 여부에 따라 달라집니다.

  * 필드의 선언 형태만 enum이나 struct로 바꾸기보다는, 어떤 참조를 실제로 보유하고 복사하는지 확인해야 합니다.

**class**

  * 클래스 참조의 복사는 객체 전체 복사와 다릅니다. 비교할 값 타입이 내부 참조를 얼마나 가지고 있는지에 따라 ARC 비용의 우열도 달라집니다.

### 결론

  * struct 내부의 참조 개수와 복사 빈도에 따라 ARC 비용도 달라집니다. 필요한 의미론을 정한 뒤 실제 작업에서 확인해야 합니다.

### Method Dispatch의 비교

**Static 함수**

  * 런타임시에 바로 함수를 찾아갑니다.

  * `final` 등으로 실제 호출 대상을 확정할 수 있으면 직접 호출과 인라이닝에 유리합니다. Whole Module Optimization은 모듈 전체 정보를 이용해 전문화·인라이닝·devirtualization 기회를 넓힙니다. 모든 함수를 무조건 static dispatch로 바꾸지는 않습니다.

**Dynamic 함수**

  * 실행시에 함수 테이블에서 함수를 찾습니다.

  * 함수의 메모리 번지로 이동합니다

  * 실행합니다.

  * 간접 호출은 직접 호출보다 비용이 들 수 있고 인라이닝 기회도 제한합니다. 다만 최적화로 직접 호출이 될 수 있으므로 차이를 항상 크다고 단정할 수는 없습니다.
